    Frontend

    This section details the repository file distributions, framework configurations, and data architecture patterns implemented across the client interface layers.

    Application Client Channels

    The FikaMarket ecosystem isolates its operational workflows across three distinct technical channels based on target user accessibility criteria:

    • Lead Farmer Portal (PWA Dashboard): Developed using Next.js to manage regional collection channels, aggregate yields, and performance tracking grids.
    • Buyer Mobile Platform: Developed using Flutter to supply native mobile processing, line-item shopping carts, escrow checkouts, and local data persistence.
    • Farmer Communication Matrix: A purely text-driven offline client matrix routing feature-phone endpoints through the system's central backend USSD gateway.

    Lead Farmer Portal Architecture (Next.js)

    The web client runs a highly structured Next.js framework designed for immediate layout rendering and clean component modularization.

    Framework Dependencies

    • Core Systems: Next.js 16.3.1 (App Router Interface) & React / React-Dom 19.2.8
    • Styling Engine: TailwindCSS and PostCSS ^4 matching global core layout variables
    • Forms Matrix: React Hook Forms driving real-time validation layers
    • Data Visualizations: Recharts metrics canvas blocks embedded directly within the dashboard view
    • Icon Assets: Lucide React optimized inline SVG vector layers
    • Typography: Roboto global font-family configurations

    Buyer Mobile Application Architecture (Flutter)

    The mobile platform delivers high runtime efficiency while preserving data usability in low-connectivity agricultural field environments.

    Data Architecture & Offline Behaviors

    • Screen Workflows: User onboarding logic is handled explicitly inside signup_screen.dart and login_screen.dart. Buyers evaluate crop lots inside market_place.dart and commit listings to cart_model.dart.
    • Offline Cache Processing: The application uses a local storage layer to cache active product tables. Users can query listings, modify carts, and stage orders completely offline. Data packets automatically sync to the FikaMarket core database once connectivity is restored.
